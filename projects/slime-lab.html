Project 02 · 인공생명 시뮬레이션

슬라임 인공생명 실험실

작은 신경망을 가진 슬라임들이 스스로 먹고 번식하며 세대를 거쳐 진화하고, 행동이 쌓이면 채집 → 저장 → 농사를 발견합니다. 사용자는 조작하지 않고 실험 조건을 정한 뒤 관찰하고 분석하는 연구용 시뮬레이션입니다. AI 코딩 에이전트(Claude Code)와 함께 바이브 코딩으로 이틀 동안 만들었습니다.

브라우저 체험판 GitHub 저장소

체험판은 PC 브라우저(WebGL2)용입니다. 브라우저에서는 데스크톱판보다 느려 높은 배속이 덜 나오며, 화면 오른쪽 위의 "실제 M배"가 그대로 보여 줍니다.

기간
2026.10.07 – 10.08
엔진
Godot 4.4.1 · GDScript
플랫폼
PC(Windows·Linux) + 웹 체험판
라이선스
MIT

01

무엇을 하는 실험인가

규칙은 단순하게, 결과는 관찰로. 모든 수치는 설정 파일 하나에서 읽습니다.

생태

먹고, 번식하고, 죽는다

64×48 격자 지도(풀밭·물·바위)는 씨앗(seed)으로 만듭니다. 식물은 비옥도 × 낮밤 × 계절 × 자원량만큼 자라고, 슬라임은 에너지와 수명이 있으며 성숙하면 가까운 짝과 번식합니다.

두뇌와 진화

작은 신경망 + 신경진화

슬라임마다 입력 12·은닉 8·출력 8 의 신경망(가중치 160개 + 크기·감지·색 유전자)이 있습니다. 역전파 없이, 번식할 때 부모의 가중치를 은닉 뉴런 단위로 섞고 돌연변이를 더해 세대가 바뀌며 진화합니다.

문명

행동이 쌓이면 발견

아직 열리지 않은 행동(줍기·내려놓기·심기)도 고를 수 있고, 그 "시도"와 결과가 쌓여 임계를 넘으면 발견이 열립니다. 저장을 발견하면 저장고가, 농사를 발견하면 밭이 생깁니다.

같은 씨앗과 같은 설정이면 같은 역사가 나오도록(결정적 시뮬레이션) 시뮬레이션 코드는 사칙연산과 제곱근만 쓰고, 이를 자동 검사로 확인합니다. 실험실에서 내보낸 CSV 는 같은 조건의 헤드리스 실행 결과와 글자까지 같습니다.

02

실험실

조작하는 게임이 아니라 관찰하는 도구입니다. 그림·모델·효과음은 모두 코드로 만들었습니다.

  • 실험 조건(예설정·씨앗·돌연변이율·자원량·초기 개체 수, 고급 설정) — 바꾼 값은 "새 실험"을 눌러야 적용
  • 속도 1~64배와 빨리 감기, 낮밤·계절, 슬라임 클릭 → 상태·가계·두뇌
  • 실시간 그래프 3개와 연대기, CSV 내보내기, 스냅숏 저장·열기
  • 두 실험 나란히 비교, 여러 씨앗을 묶어 돌리는 파이썬 분석 도구

03

실험 결과(실제 실행)

분석 도구로 여러 씨앗을 실제로 돌린 결과입니다. 꾸민 수치는 없습니다.

04

바이브 코딩으로 만든 과정

코드는 AI 에이전트(Claude Code)가 작성했고, 저는 목표와 원칙을 정하고 갈림길에서 결정하며 단계마다 결과(캡처·검사 결과)를 확인했습니다.

제가 정한 것

  • 프로젝트 목표와 원칙: 오프라인, 모든 수치는 설정 파일 하나에서, 결정적 시뮬레이션, 새 규칙마다 자동 검사, 검증한 것과 못 한 것을 구분해 보고
  • 학습 방식(신경진화)과 1단계 범위(생태 + 발견 3단계 + 건물 2종)
  • 데이터 형식(JSON + base64), 두뇌 구조는 권장안(고정 12-8-8) 채택
  • "PyTorch 를 쓰면 좋지 않을까?" — 개체마다 아주 작은 신경망·역전파 없는 진화·결정성 때문에 시뮬레이션에는 쓰지 않고, 파이썬은 결과 분석에만
  • PC 전용 원칙의 예외로 포트폴리오용 웹 체험판

AI 에이전트가 한 것

  • 설계 문서 초안, 구현, 자동 검사, 문서
  • 화면 구성 요소를 git 워크트리에서 여러 에이전트가 병렬로 만든 뒤 통합
  • 적대적 검토: 여러 관점의 검토자가 문제를 찾고, 발견마다 검증자 둘이 반박을 시도해 살아남은 것만 고침(3단계: 43건 확인 중 40건 수정)
  • GitHub Actions: 검사 → Linux·Windows·웹 빌드 → 체험판 배포
  1. 설계 규칙·데이터 구조·화면·검사 항목·성능 목표를 문서로. 바꾸기 어려운 결정 두 가지만 먼저 질문.
  2. 시뮬레이션 핵심 화면 없이 도는 규칙과 헤드리스 실행기. 초안 수치로는 첫 세대가 매번 멸종해 행동 선택을 확률적으로 바꾸고 생태 수치를 조정.
  3. 3D 실험실 절차적 슬라임 모델, 지도 관찰 창, 개체 정보 창. 병렬 개발 → 통합 → 적대적 검토.
  4. 패널과 비교 실험 조건·그래프·연대기·CSV·스냅숏·비교 모드·합성 효과음.
  5. 빌드와 배포 Linux·Windows·웹 내보내기, 자동 빌드, 체험판 배포.

약 7,700줄검사 코드

커밋 31개단계마다 커밋·푸시, CI 로 확인

과정에서 드러난 것

  • 설계 초안대로 구현하자 무작위 두뇌가 한 행동만 반복해 첫 세대가 멸종 — 실측으로 원인을 찾고 설계를 고침
  • Godot 4.4.1 의 JSON 출력이 실수를 비트 단위로 되돌리지 못함(0.1+0.2 → "0.3") — 스냅숏의 실수는 비트 문자열로 저장
  • 각자 검사를 통과한 구성 요소도 함께 띄우자 최소 창 크기에서 패널이 넘침 — 실제 화면을 띄우는 통합 검사를 추가

05

검증한 것과 확인하지 못한 것

항목판정근거
같은 씨앗 → 같은 역사통과역사 해시·CSV·유전체 비교, 서로 다른 리눅스 기계(CI)에서도 같은 해시
저장·복원 왕복통과복원 후 이어 돌린 해시 = 끊김 없이 돌린 해시
자원 0 → 멸종, 100세대 안에 농사 도달하는 조건통과자동 검사
화면을 거쳐도 시뮬레이션이 바뀌지 않음통과실험실을 거친 해시 = 헤드리스 해시
헤드리스 1,000세대7.4분목표 5분은 넘음(개체·틱당 약 16µs)
실제 GPU 에서 200마리 60FPS미검증개발 환경에 GPU 가 없어 소프트웨어 렌더러로만 측정
Windows·macOS 에서 같은 해시, Windows 실행미검증리눅스 환경만 있음
효과음을 실제로 들어 보기미검증합성 파형의 수치만 자동 검사
